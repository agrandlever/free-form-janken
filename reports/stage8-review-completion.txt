2. RoomService.startMatch()の検証順序
セッション認証 → 要求roomId/currentRoomId一致 → 現在Room取得 → 操作者/hostUserId一致 → ②または③・memberIds所属 → currentMatchId=null → memberIds入室順で現在所属するREADY取得 → 2人以上 → 全OriginalHand存在 → username非重複 → OriginalHand.name非重複 → MatchServiceへ委譲。
非ホスト403/FORBIDDEN。roomId・状態不一致、対戦中、READY不足は409/INVALID_STATE。
両名前の重複があれば両メッセージを保持し、ユーザー名を主コードにします。

3. MatchService.startMatch()の処理順序
GameMatch生成・Room情報/ルールのコピー → 入室順のMatchParticipant生成 → 全OriginalHandSnapshot生成 → Clockから第1Round生成 → MatchStore保存 → Room.currentMatchId設定 → 確定参加者だけPLAYING → IDを返却。
startMatch以外の後続メソッド・stubはありません。

4. GameStateLockで保護した範囲
RoomServiceでの認証・全検証からMatchServiceのコピー・構築・保存・Room更新・全参加者状態変更・結果作成まで、同じ単一GameStateLockを保持します。
MatchServiceはThread.holdsLock(lock)で外側の保持を確認し、委譲前後でロックを解放しません。
ready、cancelReady、rules、OriginalHand save/delete、leave、logoutと表示コピー生成も同じロックです。

5. GameMatch ID生成方法
検証成功後、ロック内のUUID.randomUUID()。不成立要求はID生成・保存に進みません。

6. participantsの生成方法と順序
