# 要件定義書：簡易自由律じゃんけん

## 1. 概要

複数ユーザーが同じルームへ参加し、通常のグー・チョキ・パーと、各ユーザーが作成したオリジナル手を利用して複数人で対戦できるWebアプリケーションを提供する。

データベースは使用せず、データはアプリケーション実行中のメモリに保持する。

## 2. 対象ユーザー

友人同士など、複数人でオンライン対戦を行いたい一般ユーザー。

## 3. ユーザー状態

| 状態 | 名称 |
|---|---|
| ① | ログイン済・ルーム未参加 |
| ② | ルーム参加・対戦準備中 |
| ③ | 対戦準備完了 |
| ④ | 対戦中 |

未ログイン状態は上記に含めない。

## 4. 簡易ログイン

- パスワードは使用しない。
- ユーザー名は1～20文字とする。
- 前後の空白を除去してから判定する。
- システム全体では同一ユーザー名を許可する。
- HTTPセッション等により内部的には別ユーザーとして識別する。
- ユーザー情報は永続化しない。

### 4.1 文字列の共通判定基準

ユーザー名・ルーム名・オリジナル手名の前後空白除去、保存、重複判定、文字数判定には、次の共通基準を適用する。

- サーバーでJava `String.strip()`の規則により前後空白を除去する。本書の「前後空白」「空白だけ」の判定も、この規則を基準とする。
- 保存・表示する値と重複判定に使用する値は、除去後の値とする。
- 文字数は除去後のUnicodeコードポイント数（Unicodeの文字を表す符号位置の個数）で数える。Java `String.length()`ではなく、`value.codePointCount(0, value.length())`を使用する。
- 「1～20文字」は、除去後のUnicodeコードポイント数が1～20であることを意味する。未入力または除去後に空になる入力は拒否する。
- JavaScript側のチェックは補助とし、最終判定はサーバーを正とする。

## 5. ルームへの入室

ユーザーはルーム名を入力し、同一の「ルームへ入る」操作でルーム作成または既存ルームへの参加を行う。

### 5.1 同名ルームが存在しない場合

- 新しいルームを作成する。
- 操作者をホストとする。
- 操作者を②へ変更する。
- 先取勝数の初期値は3とする。
- 同一オリジナル手連続使用禁止の初期値はOFFとする。

### 5.2 同名ルームが存在する場合

- 既存ルームへ参加する。
- 最大人数を超えないことを確認する。
- 操作者を②へ変更する。

### 5.3 ルーム名

- 1～20文字。
- 前後の空白を除去した後の完全一致で既存ルームを判定する。
- 同時に存在できる同名ルームは1つだけとする。
- 参加者が0人になった場合はルームを削除し、そのルーム名を再利用可能とする。
- 1ルーム最大8人。
- 対戦中のルームにも新規参加可能。
- 同時入室でも最大8人を超えない。
- 同一ユーザーが同時に複数ルームへ所属することはできない。

## 6. ルーム名の共有

ルーム画面に「ルーム名をコピー」ボタンを表示する。

押下すると現在のルーム名をクリップボードへコピーする。

ルームIDはユーザー向け機能として使用しない。ただし実装内部では内部IDを保持してよい。

## 7. ホスト

- 新規ルーム作成者をホストとする。
- ホストは対戦ルール変更と対戦開始を行える。
- ホストが退出した場合、残存ユーザーのうち最も早くルームへ参加したユーザーへホストを移譲する。
- ホスト自身が②でも、③が2人以上存在すれば対戦を開始できる。

## 8. オリジナル手

各ユーザーは1つまで所有できる。

### 8.1 作成・更新・削除可能状態

①・②。

### 8.2 操作不可状態

③・④。

### 8.3 名前

- 前後の空白を除去した後の名前を1～20文字とする。
- 未入力・空文字・空白だけの入力は不可とする。
- 前後空白除去後に「グー」「チョキ」「パー」のいずれかと完全一致する名前は、作成・更新ともに不可とする。
- 禁止名は上記3つの完全一致だけを対象とし、その文字列を含む別の名前は、他の入力条件を満たせば使用できる。
- この禁止はオリジナル手名だけに適用し、ユーザー名・ルーム名には適用しない。
- 除去後の名前を保存し、準備完了時の手名重複判定にも使用する。
- システム全体では同名を許可する。

### 8.4 相性

次の4項目について、それぞれ「勝ち」「負け」「引き分け」を設定する。

- グー
- チョキ
- パー
- 他のオリジナル手

4項目中最低1項目は「負け」とする。

## 9. オリジナル手設定UI

専用画面は設けない。

①または②の現在画面内で表示を切り替える。

### 9.1 未作成の場合

「オリジナル手を作成」を表示し、押下すると同一画面内で作成フォームを展開する。

### 9.2 作成済みの場合

作成導線は表示しない。

次を表示する。

- 現在のオリジナル手名
- 「オリジナル手を編集」

編集ボタン押下で現在値を設定したフォームを展開する。

作成・編集フォームには「決定」「閉じる」を表示する。

作成済みの場合は「オリジナル手を削除」も表示する。

## 10. 対戦準備完了条件

②から③へ遷移するには、次の条件をすべて満たす必要がある。

1. オリジナル手を作成済みである。
2. 同一ルームで現在③のユーザーとユーザー名が重複していない。
3. 同一ルームで現在③のユーザーとオリジナル手名が重複していない。

比較対象は③のユーザーのみとする。

②・④のユーザーとの重複は準備完了を妨げない。

オリジナル手が前回対戦から更新されているかどうかは準備条件に含めない。

前回公開された設定から更新せずに③へ遷移する場合でも、注意・警告・確認・更新推奨等は一切表示しない。

## 11. 対戦ルール

ホストがルーム画面内で設定する。

### 11.1 先取勝数

1～99。

### 11.2 同一オリジナル手の連続使用禁止

ON / OFF。

初期値はOFF。

ONの場合、各プレイヤーは直前ラウンドで自分が選択したオリジナル手と同一内部IDのオリジナル手を、次ラウンドでも選択できない。

通常手には制限を適用しない。

例：

- グー → グー：可
- チョキ → チョキ：可
- パー → パー：可
- グー → オリジナル手A：可
- オリジナル手A → グー：可
- オリジナル手A → オリジナル手B：可
- オリジナル手A → 同一オリジナル手A：不可

第1ラウンドでは制限しない。

前ラウンドに勝者が存在したかどうかは制限判定に影響しない。

対戦中はルール変更不可。

ルール変更によって③を解除しない。

対戦開始時点のルールを対戦終了まで固定する。

## 12. 対戦開始

- ③が2人以上存在する場合、ホストが開始できる。
- ホスト自身が②でもよい。
- 開始時点の③のみ④へ変更する。
- 正常に開始された同一対戦の参加者間では、ユーザー名とオリジナル手名がそれぞれ重複しない。

## 13. 対戦開始時の固定情報

次を固定する。

- 対戦参加者（内部IDと開始時点のユーザー名）
- 先取勝数
- 同一オリジナル手連続使用禁止設定
- 各参加者のオリジナル手
- オリジナル手名
- オリジナル手相性

作成者が途中退出しても、固定済みオリジナル手は対戦終了まで利用可能とする。

## 14. 手の選択

利用できる手：

- グー
- チョキ
- パー
- 対戦開始時に固定された全参加者のオリジナル手

他参加者が作成したオリジナル手も利用できる。

一度確定した手は同一ラウンド中変更できない。

古い対戦・ラウンドの画面から届いた手確定要求は、現在の対戦・ラウンドへの新しい入力として扱わず拒否する。

全参加者が確定するまで、他参加者および観戦者には選択内容を公開しない。

## 15. 勝敗判定

### 15.1 通常手同士

通常のじゃんけんルールを使用する。

### 15.2 オリジナル手対通常手

オリジナル手側に設定された相性を使用する。

### 15.3 同一オリジナル手

同一内部IDなら引き分けとする。

### 15.4 異なるオリジナル手

双方の「他のオリジナル手」への相性を組み合わせて判定する。

| A | B | 結果 |
|---|---|---|
| 勝ち | 負け | A勝ち |
| 負け | 勝ち | B勝ち |
| 勝ち | 勝ち | 引き分け |
| 負け | 負け | 引き分け |
| 引き分け | 勝ち | B勝ち |
| 引き分け | 負け | A勝ち |
| 勝ち | 引き分け | A勝ち |
| 負け | 引き分け | B勝ち |
| 引き分け | 引き分け | 引き分け |

## 16. ラウンド勝敗

各プレイヤーについて、

- 勝つ相手が1人以上存在する
- 負ける相手が0人

の両方を満たした場合に1勝を加算する。

同一ラウンドで複数人が勝利できる。

誰も勝利しないラウンドも存在する。

## 17. ラウンド結果からの自動遷移

ラウンド結果確定時点から、

- 勝利者あり：10秒
- 勝利者なし：5秒

ラウンド結果を表示する。

手動の「次のラウンドへ」ボタンは設けない。

期限到達後の次回MatchTransitionScheduler実行で、

- 未決着 → 次ラウンド
- 決着 → 対戦結果

へ自動遷移する。

最終ラウンドも結果確定＋10秒を期限とし、期限到達後の次回Scheduler実行で正常終了してから、次回状態確認で対戦結果へ進む。

最終ラウンドの勝者確定後は、10秒の期限到達後の正常終了処理が完了するまで、残存対戦参加者を④のままとし、切断で通常結果を中止へ変更しない。

### 17.1 時間仕様の共通基準

5秒・10秒・30秒はサーバー上の期限として扱い、実時間での画面切替との完全一致を要求しない。

- ラウンド結果の期限は結果確定時刻＋5秒または＋10秒、通信切断の期限は最後の正常状態確認時刻＋30秒とする。入室直後は入室時刻を通信監視の基準とする。
- 期限より前に、時間経過を理由とする状態遷移・切断処理を行ってはならない。
- MatchTransitionScheduler（対戦の自動遷移を確認する定期処理）は500ms間隔、DisconnectMonitor（切断を確認する定期処理）は1秒間隔で確認し、期限到達後の次回実行時に、共通ロック内で最新の状態と時刻を確認して更新する。
- ブラウザーの状態確認は2秒間隔とし、サーバー状態変更後の次回状態確認で表示へ反映されればよい。カウントが0になったことだけで画面側が状態を確定しない。
- 時間依存ロジックはJava `Clock`等（現在時刻を取得する仕組み）を利用し、テストで現在時刻を制御可能にする。期限前の非遷移と期限到達後のScheduler実行による遷移を分けて検証し、実時間の完全一致を合否条件にしない。

人数不足による即時中止や手動退出等、時間経過によらない既存の処理はこの待機期限の対象ではなく、従来どおり実行する。最終勝者確定後は、期限到達後の正常終了処理が完了するまで正常結果の保護と残存参加者の④を維持する。

## 18. ラウンド履歴

対戦画面で表示／非表示を切り替えられる。

初期状態は非表示。

表示内容：

- ラウンド番号
- ユーザー名
- 選択した手
- そのラウンドで勝利したか

累積勝数は履歴内に表示しない。

勝利者には「勝利」と文字表示し、背景・枠・太字等でも強調する。

色だけに依存しない。

勝者なしの場合は「このラウンドの勝者はいません」と表示する。

確定済み履歴は、その後参加者が退出しても削除しない。

## 19. 観戦

進行中対戦に参加していない同一ルームの②・③は対戦を観戦できる。

観戦者は手を選択できない。

ラウンド履歴は閲覧できる。

観戦画面からルームへ戻れる。

## 20. 通信切断・途中退出

状態確認を2秒間隔で行う。

最後の正常確認＋30秒の期限到達後、次回DisconnectMonitor実行で最新lastSeenAtを再確認して切断扱いとする。17.1節の時間仕様を適用する。

対戦参加者が途中退出した場合、

- 残り2人以上：対戦継続
- 残り1人以下：勝者なしで対戦中止

とする。

不戦勝にはしない。

手選択中に退出したユーザーとその提出済み手は、現在ラウンドの判定対象から除外する。

その結果、残存参加者が2人以上で、全員の手が確定済みになった場合は直ちに判定する。

未決着ラウンドの結果表示中に退出した場合、残り2人以上なら対戦を継続するが、確定済みのラウンド結果・履歴・勝数・遷移時刻を変更せず、再判定もしない。次ラウンドから退出者を除外する。残り1人以下なら即時中止する。

最終勝者確定後は、残り人数が0人になっても正常結果を変更せず、結果確定＋10秒の期限到達後の次回MatchTransitionScheduler実行で正常終了する。全員退出によりルームが削除されても、この終了処理を完了する。

退出者の開始時点のユーザー名、過去ラウンド履歴、獲得済み勝数は対戦記録として保持する。

途中退出者も、終了済み対戦の参加者一覧と最終勝数から除外しない。

## 21. 対戦終了時の相性公開

対戦終了後、対戦開始時に固定されたすべてのオリジナル手相性を閲覧できる。

初期状態は非表示。

「オリジナル手の相性を表示」で表示し、再度押すと非表示にできる。

表示形式は表形式とする。

通常終了・対戦中止の双方で利用できる。

## 22. 対戦結果画面からのオリジナル手編集

相性表を展開した場合、現在のユーザーが②ならオリジナル手設定への導線を表示する。

作成済みの場合は「自分のオリジナル手を編集」を表示する。

未作成の場合は「オリジナル手を作成」を表示する。

押下すると同じ対戦結果画面内でフォームを展開する。

③の場合は作成・編集導線を表示しない。

編集後も終了済み対戦の相性表は変更しない。

更新内容は次回以降の対戦に適用する。

### 22.1 対戦終了後のユーザー状態

正常終了時は、最終ラウンドの結果確定＋10秒の期限到達後、次回MatchTransitionScheduler実行で正常終了処理を行う時点に、現在も同じルームに残っている対戦参加者を④から②へ変更する。

対戦中止時も、その対戦の残存④参加者は終了時に②へ変更する。

対戦に参加していない観戦者は、正常終了・対戦中止のいずれでも状態を変更しない。

- ②の観戦者 → ②のまま。
- ③の観戦者 → ③のまま。

既に退出・切断して①になったユーザーを②へ戻さない。

### 22.2 終了済み対戦結果の閲覧

対象の対戦が行われたルームに現在所属する②・③は、終了済み対戦の結果を閲覧できる。対戦参加者だったかどうかは条件に含めない。

未ログインユーザー、①、他ルーム所属ユーザーには、そのルームの結果を公開しない。

結果画面の「ルームへ戻る」は、そのタブを現在ルームの画面へ移動するだけで、②・③の状態を変更しない。他のタブの閲覧対象も変更しない。

対戦・観戦から結果画面へ自動遷移するときは、その画面で扱っていた対戦の結果を表示する。遷移が遅れて別の対戦が終了していても、別対戦の結果へ置き換えない。

### 22.3 結果画面の維持と次対戦

終了済み対戦結果を閲覧中の②は、新しい対戦が始まっても、原則として本人が「ルームへ戻る」を押すまで同じ結果画面を維持する。

その後の対戦が終了しても、閲覧中の過去結果を新しい結果へ自動的に置き換えない。

結果の閲覧対象はタブごとに維持する。別タブでルームへ戻る、観戦する、別の終了済み結果を開く等の操作をしても、元のタブの結果は再読み込み・作成・編集・削除後を含めて維持する。

退出・切断・ログアウトで閲覧条件を失った場合はアクセス制御を優先する。

同様に、閲覧中の③も次対戦に参加しない限り同じ結果を維持する。

ただし、別タブ等で準備完了した本人が次対戦の開始によって③から④になった場合は、新しい対戦の現在の進行状態に合った画面へ自動遷移する。

## 23. 非機能・技術要件

- バックエンド：Java 21 / Spring Boot 4.1.1
- ビルド：Gradle。Gradle Wrapperを使用する。
- 使用技術：Spring Web、Thymeleaf、Validation、Spring Boot Test
- フロントエンド：HTML / CSS / JavaScript
- テンプレート：Thymeleaf
- DB：使用しない。JPA、H2等のDB関連依存関係を追加しない。
- アプリケーション再起動による一時データ消失を許容する
