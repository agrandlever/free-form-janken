# 機能仕様書：簡易自由律じゃんけん

## 1. 前提

- パスワードなしの簡易ログイン方式とする。
- DBは使用しない。
- 1ルーム最大8人。
- 1ルームで同時に進行できる対戦は1つ。
- 対戦は2人以上。
- 3人以上の対戦を許可する。
- 各ユーザーはオリジナル手を1つまで所有できる。
- 対戦非参加の同一ルームユーザーも観戦可能。

## 2. ユーザー状態

| 状態 | 名称 |
|---|---|
| ① | ログイン済・ルーム未参加 |
| ② | ルーム参加・対戦準備中 |
| ③ | 対戦準備完了 |
| ④ | 対戦中 |

## 3. 簡易ログイン

### UC-001｜ログインする

1. ユーザーが `/` へアクセスする。
2. ユーザー名を入力する。
3. システムが前後空白を除去する。
4. 1～20文字であることを確認する。
5. HTTPセッション等による内部ユーザー識別情報を作成する。
6. 状態①とする。
7. ルーム作成・参加画面へ遷移する。

ユーザー名重複を許可する。

## 4. ログアウト

### UC-002｜ログアウトする

1. ユーザーがログアウトする。
2. ルーム参加中なら退出処理を行う。
3. 対戦中なら途中退出処理を行う。
4. ホストなら必要に応じてホスト移譲する。
5. セッション上のログイン状態を終了する。

## 5. ルーム作成・参加

### UC-003｜ルームへ入る

①のユーザーがルーム名を入力して「ルームへ入る」を実行する。

処理：

1. セッションのユーザーが①かつルーム未所属であることを確認する。
2. 前後空白を除去する。
3. 1～20文字を検証する。
4. 同名ルームを検索する。
5. 存在すれば既存ルームへ参加する。
6. 存在しなければ新規ルームを作成する。

①・未所属の確認をルーム名の入力値検証より先に行う。②・③・④からの要求は、ルーム名が不正でも状態不一致として拒否し、所属・ユーザー状態・ルームを変更しない。

### 5.1 新規ルーム作成

- 操作者をホストとする。
- 操作者を②へ変更する。
- 先取勝数は3。
- 同一オリジナル手連続使用禁止はOFF。

同名ルームが同時に複数作成されないよう、「検索→なければ作成」を一連の排他的処理として扱う。

### 5.2 既存ルーム参加

- 最大人数8人未満であること。
- ユーザーが①であること。
- 対戦中でも参加可。
- 対戦中に参加したユーザーは②となり、現在対戦には参加しないが観戦できる。
- 同時要求でも「①・未所属の確認→ルーム検索／作成→人数確認→参加登録→②への変更」を一連の排他的処理とする。
- 7人のルームへ2人が同時入室した場合は1人だけ参加し、もう1人は満員として拒否する。
- 同一ユーザーが別ルームへ同時入室した場合は1要求だけ成立し、他方を状態不一致として拒否する。拒否された要求で空ルームや二重所属を残さない。
- 正常入室時を通信監視の開始基準とし、最初の状態確認までの30秒を確保する。

## 6. ルーム退出

### UC-004｜ルームから退出する

対象：②・③・④。

操作入口：

- ②・③：ルーム画面の「ルームを退出」。
- ④：対戦画面またはラウンド結果画面の「ルームを退出」。手確定後の待機中・最終ラウンド結果の10秒表示中も操作可能。
- ②・③が観戦画面や対戦結果画面にいる場合は、「ルームへ戻る」でルーム画面へ移動してから退出する。

ホスト・非ホストとも実行可能。表示中のルームIDを指定して退出を要求する。

1. ユーザーをルームから除外する。
2. 状態①へ変更する。
3. ホストなら最古参の残存参加者へホストを移譲する。
4. 参加者0人ならルームを削除する。
5. 退出前に④だった場合は、退出前の対戦IDを使用して対戦途中退出処理も行う。

退出前の状態・所属ルーム・対戦IDを先に保存し、同じ排他処理内で実行する。①への変更後に④かどうかを再判定しない。

0人によるルーム削除は、必要な途中退出処理後に行う。最終勝者確定後の正常終了待ち対戦は、ルーム削除後も予定時刻に終了する。

手動の「ルームを退出」ではログインセッションと本人のオリジナル手（内部ID・名前・相性）を維持し、①のルーム作成・参加画面へ戻す。③の準備状態は退出によって終了し、④の対戦への影響は22節に従う。別タブも次の状態確認で①の画面へ移動する。

## 7. ルーム名コピー

ルーム画面の「ルーム名をコピー」ボタンで現在のルーム名をクリップボードへコピーする。

成功時は「ルーム名をコピーしました」と表示する。

## 8. オリジナル手作成・編集

専用画面は使用しない。

### 8.1 ①

ルーム作成・参加画面内で作成・編集する。

### 8.2 ②

ルーム画面内で作成・編集する。

### 8.3 対戦結果画面の②

相性表展開部分から作成・編集できる。

### 8.4 導線

未作成：

- 「オリジナル手を作成」

作成済み：

- 現在の手名
- 「オリジナル手を編集」

作成済みの場合に「作成」は表示しない。

## 9. オリジナル手設定

設定項目：

- 名前
- グーへの相性
- チョキへの相性
- パーへの相性
- 他のオリジナル手への相性

名前は、前後空白を除去した後に1～20文字であることを判定する。

未入力・空文字・空白だけの場合は保存しない。除去後の名前を保存・表示し、準備完了時の重複比較に使用する。

前後空白除去後の名前が「グー」「チョキ」「パー」のいずれかと完全一致する場合は保存しない。禁止名を含む別の名前は、他の入力条件を満たせば使用できる。

禁止名の場合は、同じフォーム内に `オリジナル手の名前に「グー」「チョキ」「パー」は使用できません。` を表示する。不正な更新では既存の名前・相性・内部IDを変更しない。

作成・更新の双方と、①・②・対戦結果画面②の全作成／編集フォームに同じ検証を適用する。この禁止はオリジナル手名だけを対象とする。

相性は `WIN / LOSE / DRAW`。

全4項目必須。

最低1項目を `LOSE` とする。

作成済みの場合は更新。

削除も①・②のみ可能。

## 10. 準備完了

### UC-005｜準備完了する

対象：②。

処理順：

1. オリジナル手の存在を確認。
2. 同一ルームの③ユーザーを取得。
3. ユーザー名重複を確認。
4. オリジナル手名重複を確認。
5. 問題がなければ③へ変更。

上記の確認から③への変更までをルーム単位の一連の排他的処理とする。同じユーザー名または手名のユーザーが同時に要求しても、③同士の重複を発生させない。

先に成立した要求だけを③にし、後の要求は更新後の③一覧で判定して、該当する重複エラーを返す。

### 10.1 オリジナル手なし

②のまま。

表示：

`オリジナル手を作成してから準備完了してください。`

### 10.2 ユーザー名重複

②のまま。

表示：

`準備完了中のプレイヤーとユーザー名が重複しています。`

### 10.3 オリジナル手名重複

②のまま。

表示：

`準備完了中のプレイヤーとオリジナル手の名前が重複しています。`

ユーザー名・手名の両方が重複した場合は、両メッセージをまとめて表示する。

### 10.4 前回対戦から未更新

オリジナル手を前回対戦から更新していなくても準備完了可能。

注意・警告・確認ダイアログ等は一切表示しない。

## 11. 準備取消

### UC-006｜準備取消する

③→②。

取消後、そのユーザー名・オリジナル手名は他ユーザーの準備完了判定対象としない。

## 12. ルール変更

### UC-007｜ルールを変更する

ホストのみ。

ルーム画面内で行う。

設定：

- 先取勝数 1～99
- 同一オリジナル手連続使用禁止 ON/OFF

対戦中は変更不可。

ルール変更しても③を維持する。

## 13. 対戦開始

### UC-008｜対戦を開始する

条件：

- 進行中対戦なし。
- ③が2人以上。
- 実行者がホスト。

処理：

1. 開始時点の③を取得する。
2. ③のみ対戦参加者として、内部IDと開始時点のユーザー名を固定。
3. 先取勝数を固定。
4. 同一オリジナル手連続使用禁止設定を固定。
5. 各参加者のオリジナル手と相性を固定。
6. ③→④。
7. 第1ラウンド開始。

ホストが②なら②のまま観戦可能。

## 14. 対戦観戦

### UC-009｜対戦を観戦する

対象：

同一ルームに所属し、現在対戦に参加していない②または③。

表示：

- 現在ラウンド
- 先取勝数
- 対戦参加者
- 累積勝数
- ラウンド履歴

制限：

- 手選択不可。
- ラウンド確定前は参加者の選択手非公開。
- 観戦画面からルームへ戻れる。

本人が進行中対戦の観戦を選び、観戦画面へ移った場合は、そのタブで観戦対象の対戦IDを保持する。元の結果画面が別タブにある場合、その閲覧対象は変更しない。

画面を移動しても②・③の状態は変更しない。ルーム画面の②・③を対戦状態だけで観戦画面へ強制移動しない。「対戦を見る」を本人が押した場合に観戦を開始する。

## 15. 手を選択する

### UC-010｜手を選択する

対象：④。

選択可能：

- グー
- チョキ
- パー
- 対戦開始時に固定した全オリジナル手

処理：

1. 要求に含まれる対戦ID・ラウンド番号が、本人の現在の対戦・ラウンドと一致することを確認。
2. 選択内容検証。
3. 同一オリジナル手連続使用禁止の検証。
4. 手を確定。
5. 同一ラウンド中は変更不可。
6. 全員確定まで他人の手は非公開。

同一ラウンドで既に手を確定済みのユーザーからの再確定は、同じ手でも別の手でも拒否する。

対象ID・ラウンド番号の確認、未確定の確認と登録は排他的に行い、同時要求でも1回だけ受け付ける。再要求で提出済み手を上書きしたり、判定・勝数加算を二重に行ったりしない。

前ラウンドや前対戦の要求が遅れて届いても、現在の未確定ラウンドへ流用しない。拒否時は手・勝数・対戦状態を変更しない。

同一ユーザーが同じ対戦・ラウンドを複数タブで表示している場合、一方で手を確定した後、他方も次の正常な状態確認で本人の確定状況と本人の選択手を反映し、すべての手選択ボタンを操作不可にする。まだ他参加者を待つ間も、他人の選択内容は公開しない。

同じ対戦・ラウンドで確定済みとなった画面を、遅れて届いた未確定時点の応答で未確定表示へ戻さない。次ラウンドでは新しいラウンドの未確定状態と連続使用制限に従って選択可能な手を更新する。結果表示中・対戦終了・退出時は既存の画面遷移を優先する。

## 16. 同一オリジナル手連続使用禁止

設定OFF：

すべての手を連続使用できる。

設定ON：

通常手は制限しない。

現在選択しようとしている手がオリジナル手の場合だけ直前ラウンドを確認する。

- 直前もオリジナル手かつ同一内部ID → 選択不可
- 別オリジナル手 → 選択可
- 直前が通常手 → 選択可
- 現在が通常手 → 制限なし

判定は各プレイヤー個別に行う。

## 17. 勝敗判定

### 17.1 通常手同士

通常のじゃんけんルール。

### 17.2 オリジナル手対通常手

オリジナル手側の設定を使用する。

### 17.3 同一オリジナル手

同一内部IDなら引き分け。

### 17.4 異なるオリジナル手

双方の `vsOriginal` を組み合わせる。

| A | B | 結果 |
|---|---|---|
| WIN | LOSE | A勝ち |
| LOSE | WIN | B勝ち |
| WIN | WIN | 引き分け |
| LOSE | LOSE | 引き分け |
| DRAW | WIN | B勝ち |
| DRAW | LOSE | A勝ち |
| WIN | DRAW | A勝ち |
| LOSE | DRAW | B勝ち |
| DRAW | DRAW | 引き分け |

## 18. ラウンド判定

全active参加者の手が確定すると判定する。

各参加者について、

- 勝つ相手が1人以上
- 負ける相手が0人

なら1勝加算する。

同一ラウンドで複数人への同時加算可。

誰も加算されない場合もある。

## 19. ラウンド結果

表示：

- ラウンド番号
- ユーザー名
- 選択手
- 当該ラウンドで勝利したか
- 現在の累積勝数

個別の相性関係は表示しない。

## 20. ラウンド自動遷移

結果確定時にサーバー側で遷移時刻を決定する。

- 勝者あり：10秒後
- 勝者なし：5秒後

期限到達後：

- 未決着 → 次ラウンド
- 決着済み → 対戦結果

「次のラウンドへ」ボタンは設けない。

最終ラウンドも10秒表示してから終了する。

最終勝者確定後の10秒間に切断が起きても、確定した正常結果を中止に変更しない。

## 21. ラウンド履歴

対戦参加者・観戦者の双方が閲覧可能。

初期状態は非表示。

「ラウンド履歴を表示」で展開し、「ラウンド履歴を非表示」で閉じる。

表示：

- ラウンド番号
- ユーザー名
- 選択手
- 勝利表示

非表示：

- 累積勝数
- 誰が誰に勝ったか
- オリジナル手相性

勝者なしの場合は「このラウンドの勝者はいません」と表示する。

## 22. 途中退出

退出者はactive対象から除外するが、開始時の参加者記録自体は削除しない。

### 22.1 手選択中・最終勝者未確定

残り2人以上：

- 対戦継続。
- 現在ラウンドから退出者の提出済み手を除外。
- 残存参加者全員の手が確定済みなら、そのラウンドを1回だけ直ちに判定。

残り1人以下：

- 勝者なしで即時中止。
- `ABORTED` とする。

### 22.2 未決着ラウンドの結果表示中

残り2人以上なら、確定済み結果・履歴・獲得済み勝数・直前手・遷移時刻を維持する。提出済み手を削除せず、再判定・再加算・表示時間の再設定もしない。次ラウンドから退出者を除外する。

残り1人以下なら即時中止する。中止しても、既に確定したラウンド履歴と獲得済み勝数は残す。

### 22.3 最終勝者確定後の10秒表示中

退出者をactive対象とルームから除外しても、確定した勝者・勝数・最終ラウンド・遷移時刻は変更しない。

残り1人以下、または0人でも中止に変更せず、予定の10秒後に正常終了する。

全員退出でルームが削除されても、開始時に固定した情報だけから正常終了結果を保存する。同じ名前で新しいルームが作られても、その新ルームを旧対戦の終了処理で変更しない。

途中退出者の内部ID・開始時点のユーザー名・過去の確定済み履歴・獲得済み勝数・固定済みオリジナル手は対戦記録に残す。

退出者も終了済み対戦の参加者一覧と最終勝数に含める。

## 23. 対戦終了

正常終了：

先取勝数到達者を勝者とする。

複数人が同一ラウンドで到達した場合は全員同時優勝。

最終ラウンド結果の10秒表示後、最終結果表示へ移る時点で、同じルームに残っている当該対戦参加者のみ④→②。

中止：

`参加人数が不足したため対戦を終了しました`

`勝者はいません`

を表示する。中止時点で同じルームに残っている当該対戦の④参加者を②へ変更する。

### 23.1 非参加者の状態

正常終了・中止とも、対戦非参加の観戦者は状態を維持する。

| 終了直前の状態・役割 | 終了後の状態 |
|---|---|
| 当該対戦の残存参加者④ | ② |
| 対戦非参加の観戦者② | ② |
| 対戦非参加の観戦者③ | ③ |
| 退出・切断済みの① | ① |

### 23.2 終了済み結果の閲覧

対象対戦のルームに現在所属する②・③は、参加・観戦の別を問わず終了済み結果を閲覧できる。

結果は終了時のスナップショット（変更しない保存用コピー）から生成する。開始時の全参加者名と最終勝数を表示し、途中退出者も除外しない。

未ログイン・①・他ルーム所属ユーザーには対象結果を公開しない。

「ルームへ戻る」はそのタブを現在ルーム画面へ戻す操作であり、②・③の状態と他タブの閲覧対象は変更しない。

対戦・観戦から結果画面へ進む際は、終了した対象対戦IDを指定する。表示が遅れて別対戦が終了していても、対象を最新結果へ置き換えない。

### 23.3 閲覧中の結果と次対戦

②が結果画面を閲覧中なら、次対戦の開始・進行・終了によってその結果画面を自動的に切り替えない。本人が「ルームへ戻る」を押すまで、閲覧中の対戦を維持する。

閲覧中の③についても、次対戦に参加しない間は同様に維持する。

ただし、本人が次対戦開始で③→④になった場合は、閲覧していた過去結果より新しい対戦を優先し、手選択中は対戦画面、ラウンド結果表示中はラウンド結果画面へ遷移する。

結果の対象は各タブのURLとフォームに保持する。別タブのルーム戻り・観戦・結果表示によって元タブの対象を変更しない。元タブの再読み込み・オリジナル手の作成／更新／削除後も同じ結果を表示する。

別タブ等での準備操作によるユーザー状態変化は、2秒間隔の状態確認で全タブへ反映する。

閲覧中も状態確認を継続し、退出・切断・ログアウト時には既存の画面アクセス制御を適用する。

## 24. オリジナル手相性公開

対戦開始時スナップショットから表を生成する。

初期状態は非表示。

「オリジナル手の相性を表示」で展開。

列：

- オリジナル手
- グー
- チョキ
- パー
- 他のオリジナル手

通常終了・中止の双方で閲覧可能。

途中退出者のオリジナル手も表示する。

## 25. 相性公開後の編集

相性表を展開しているユーザーが②の場合：

- 作成済み → `自分のオリジナル手を編集`
- 未作成 → `オリジナル手を作成`

を表示する。

同一画面内にフォームを展開する。

更新後も終了済み対戦の相性表は変更しない。

更新を行わず、そのまま後で③へ進んでも警告しない。

③の場合は編集導線を表示しない。

## 26. 通信監視

2秒間隔で状態確認。

最後の正常確認から30秒以上経過した場合は切断扱い。

②・③：

- ルーム退出
- 状態①
- 必要ならホスト移譲
- 0人ならルーム削除

④：

- 対戦とルームから退出
- 対戦参加人数に応じて継続または中止
