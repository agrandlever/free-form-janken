# 画面設計書：簡易自由律じゃんけん

## 1. 基本方針

- PC・スマートフォン双方を対象とする。
- 画面幅に応じて折り返し・配置切替・表の横スクロールを行う。具体的な条件は19節に従う。
- 主要コンテンツは中央寄せとする。
- 勝敗・状態の意味を色だけで表現しない。
- 同名ユーザー・同名オリジナル手はシステム全体では許可する。
- 対戦開始時点では準備完了条件により参加者間のユーザー名・オリジナル手名は重複しない。

### 1.1 文字列入力の共通基準

ユーザー名・ルーム名・オリジナル手名の前後空白除去、保存、重複判定、文字数判定には、次の共通基準を適用する。

- サーバーでJava `String.strip()`の規則により前後空白を除去する。本書の「前後空白」「空白だけ」の判定も、この規則を基準とする。
- 保存・表示する値と重複判定に使用する値は、除去後の値とする。
- 文字数は除去後のUnicodeコードポイント数（Unicodeの文字を表す符号位置の個数）で数える。Java `String.length()`ではなく、`value.codePointCount(0, value.length())`を使用する。
- 「1～20文字」は、除去後のUnicodeコードポイント数が1～20であることを意味する。未入力または除去後に空になる入力は拒否する。
- JavaScript側のチェックは補助とし、最終判定はサーバーを正とする。

HTMLのmaxlengthやJavaScriptの文字列lengthだけで「20文字」を判定し、サーバーで有効な入力を送信できなくしてはならない。入力補助を設ける場合も上記のコードポイント数を基準とし、保存・重複判定・入力エラーはサーバーの結果を反映する。

### 1.2 共通の見た目と画像

- Bootstrap 5.3.8（ボタン・フォーム・表などの見た目を整えるCSSライブラリ）をローカル配信し、全6画面でBootstrapのCSS、独自の`/css/style.css`の順に読み込む。開閉操作は独自JavaScriptで行う。
- 主要コンテンツは白い背景・角丸・枠線・影を持つ中央の領域へ配置する。通常画面は最大幅920px、ログインは最大幅520pxとする。
- 全6画面に`/favicon.png`をPNG形式のfavicon（ブラウザーのタブに表示するアイコン）として指定する。
- ログインとログイン後の共通ヘッダーは`/images/icon.png`と`/images/logo.png`を組み合わせる。アイコンは装飾として代替テキストを空にし、ロゴの代替テキストを「簡易自由律じゃんけん」とする。縦横比を維持する。
- ログインはアイコンの下にロゴを配置する。アイコン幅は親領域の幅・260px・画面高さの30%の最小値、ロゴ幅は360pxを上限として親領域に収める。
- ヘッダーのアイコンとロゴは横並び。通常のブランド領域幅は`clamp(220px, 40vw, 392px)`、アイコン幅80px、ロゴ幅300pxを上限とし、領域内に収める。575.98px以下はブランド領域幅392pxを親幅内に縮め、アイコン幅60pxとする。ブランド領域の高さは通常`64px × 1199 / 1312`、小画面は`48px × 1199 / 1312`とし、画像はヘッダーの上下余白を利用する。
- 背景は768px未満で`/images/background-mobile.png`、768px以上で`/images/background-pc.png`を使用する。中央配置・繰り返しなし・`cover`（領域を覆う大きさ）・ページとともにスクロールする表示とする。未読込時の背景色は`#f3f6fc`。
- 文字の基本色は`#26334a`、見出しや案内の強調は`#173664`とする。準備操作・相性案内は淡い青の背景、保存済み要約・ルール要約・参加者は枠付きの領域で区切る。主要操作は青、準備取消は控えめな枠線、退出は赤い枠線で示し、文字でも操作内容を区別する。
- 入力欄・相性選択ラベル・開閉見出しは高さ48px以上、ボタンは高さ44px以上を確保する。キーボードのフォーカス位置は3pxの濃い枠と外側の白い余白で示す。相性選択はラベル全体を押せ、選択済みを背景・枠・太字で強調する。Windowsのコントラストテーマでは選択枠にシステムの強調色を使う。
- SCR-003の主要領域は768px以上で内側余白32pxとする。他画面と768px未満の左右余白は従来どおりとする。ルーム内の説明・要約・編集導線の余白は7節・19節に従う。
- 参加者の役割と準備状態は別のラベルで示す。ホストは中立色、準備前は灰色、準備完了は緑、現在対戦中は青とし、色だけで区別しない。具体的な色と文字の扱いは9節に従う。

### 1.3 エラーと文字の見やすさ

- HTTPステータス・errorCode・errorMessages・fieldErrorsを維持し、内部コードを画面の見出しや本文には表示しない。入力不正の見出しは「入力内容を確認してください」、その他は「操作を完了できませんでした」とする。
- 概要は1か所に表示する。修正可能な項目へのリンクを概要へ列挙し、具体的なメッセージは欄の下へ1回だけ表示する。項目に対応しないエラーは概要へすべて表示し、複数の業務エラーも省略しない。
- 相性の未選択・不正値は「グーへの相性を選んでください。」等、4項目を区別する。元の業務エラーModelとは別に表示専用Modelで整形する。
- 「相性4項目のうち最低1項目は負けにしてください。」は4項目全体の条件として、フォーム内のエラー概要へ1回だけ表示する。概要の「相性4項目を確認する」から共通領域へフォーカスとスクロールを移す。この条件だけでは個別欄を赤くせず、個別のaria-invalidも設定しない。共通領域は名前付きのグループとして概要内の全体エラーをaria-describedbyで参照する（6節）。
- 個別エラーと全体エラーは独立して分類し、併存時も必要なメッセージとリンクを省略・重複させない。修正可能な個別エラーがあれば最初の不正入力へ、全体条件だけなら概要へ初期フォーカスを移す。リンクによる移動を含め、フォーカス移動ではラジオの選択を変更しない。
- 入力値・フォームの展開状態・サーバー検証を維持する。不正な入力にaria-invalid="true"を設定し、aria-describedbyで項目エラーに関連付ける。再表示時は最初の修正可能な入力、項目がなければ概要へフォーカスを移す。概要のリンクからも入力へ移動できる。
- 淡い灰色背景上の青い枠線ボタン・青文字・リンクは#0b5ed7を基本とし、通常サイズの文字はコントラスト比4.5:1以上を確保する。ホバー・フォーカス・選択済みでも読め、既存の濃いフォーカス枠を維持する。

## 6. オリジナル手のインラインフォーム

作成ボタンまたは編集ボタン押下で同一画面内へ展開する。

```text
オリジナル手

名前
[                    ]

グー
( ) 勝ち
( ) 負け
( ) 引き分け

チョキ
( ) 勝ち
( ) 負け
( ) 引き分け

パー
( ) 勝ち
( ) 負け
( ) 引き分け

他のオリジナル手
( ) 勝ち
( ) 負け
( ) 引き分け

[ この手を保存 ]
[ 閉じる ]
```

作成済みの編集時は、

```text
[ オリジナル手を削除 ]
```

も表示する。

見出しはSCR-002で「オリジナル手の作成（入室前は任意）」、SCR-003・006で「オリジナル手の設定」とする。見出し付近に「作った手は、対戦参加者全員が選べます。」「他の人の相性は、対戦終了後に確認できます。」「相性4項目は必須です。最低1項目は「負け」にしてください。」の3点を、フォームを閉じていても常時表示する。名前のラベルは「オリジナル手の名前」とし、入力欄の下に補足「1～20文字（前後の空白は除きます）」を表示する。入力欄から補足とエラーを参照できるようにする。

作成済みの場合、フォームを閉じていても「保存した手：手名」と「保存した手から見た相性設定」を表示する。要約の項目は「対グー」「対チョキ」「対パー」「対オリジナル」で、値は「勝ち」「負け」「引き分け」。未作成では相性要約を隠す。入力エラー時も要約は保存済み値とし、再表示した未保存の入力と混ぜない。

必須・最低1項目が負けという案内は上記の常時表示へまとめ、相性欄の前では勝ち・負け・引き分けが自分の手から見た設定であることを説明する。「相性の決まり方」は初期状態で閉じ、押下で説明と例表を開閉する。通常手には自分の設定を使い、異なるオリジナル手同士は双方の設定で決まることを説明する。双方が勝ちなら引き分け、自分が勝ち・相手が負けなら自分の勝ち、という例に続けて機能仕様書17.4節の9通りを自分から見た結果で示す。同一内部IDの手同士の判定は既存仕様を維持する。

相性4項目はそれぞれ枠付きの選択グループとし、勝ち・負け・引き分けから1つを選ぶ。列数と小画面での選択肢の配置は19節に従う。閉じる操作で入力を消さず、再展開時も同じ入力を保持する。

4項目を囲む共通領域は`id="affinity-fields"`・`role="group"`・`aria-label="相性4項目"`・`tabindex="-1"`を持ち、通常のTab順序には追加しない。常時説明と相性の意味をaria-describedbyで参照し、全体条件エラー時は概要内の`affinity-group-error`も参照する。全体条件は個別欄の下へ再掲しない。未選択・不正値は各項目のエラー・リンク・aria-invalidを維持する。概要から共通領域への移動後はTab／Shift＋Tab・矢印キーで修正でき、移動だけで選択値を変更しない。この表示とフォーカスはSCR-002・003・006の共通フォームに適用する。

名前の入力制約：

- 前後空白を除去した後に1～20文字。
- 未入力・空文字・空白だけの入力は保存不可。
- 前後空白除去後に「グー」「チョキ」「パー」のいずれかと完全一致する名前は保存不可。部分一致では禁止しない。
- 禁止名の場合は `オリジナル手の名前に「グー」「チョキ」「パー」は使用できません。` を同じフォーム内に表示する。入力値を保持し、フォームを展開したままにする。
- エラーは同じフォーム内に表示し、不正な名前を保存しない。
- 作成・編集の双方と、ルーム作成・参加画面、ルーム画面、対戦結果画面の全オリジナル手フォームに適用する。
- 相性4項目はすべて必須で、最低1項目は「負け」。不正時は同じフォームにエラーを表示する。
- 保存・削除後は操作した画面へ戻る。結果画面では同じ対戦の結果を維持する。
- フォームには返却先と必要な内部roomId・resultMatchIdを制御用に保持し、画面には表示しない。
- 別タブで③・④になった場合は作成・編集・削除を操作不可にし、旧フォームの送信もサーバー側で拒否する。

## 7. SCR-003｜ルーム

基本表示：

```text
ルーム：自由律部屋

[ ルーム名をコピー ]

参加者一覧
参加者 ○人・準備完了 ○人
参加者名・ホスト・準備状態

対戦の準備
本人の案内・作成／準備／開始・待機案内・観戦導線

対戦ルール（要約・変更の開閉）

オリジナル手の設定

[ ルームを退出 ]
```

コピー成功時：

```text
ルーム名をコピーしました
```

内部ルームIDは表示しない。

上記の順に配置する。ルーム名とコピー操作は幅に応じて横並び・折り返しとし、退出操作は最下部で区切り線により分離する。

768px以上では主要領域の内側余白を32px、準備・ルール・手設定の外側上下余白を各16pxとする。手設定の内側余白は20px、見出し・常時説明・保存済み相性要約の下余白は12px、保存した手名の下余白は8pxとする。編集パネルの上余白・区切り線からの内側余白は各12pxとする。説明・要約は常時表示し、見出し・入力・ラベル・ボタンの最小高さと相性グループ間16pxは維持する。

「ルームを退出」は②・③のホスト・非ホストへ表示し、ルームで対戦が進行中でも操作可能とする。roomActionFormのhidden項目（画面には表示しない送信用項目）に表示中のroomIdを保持し、POST /room/leaveへ送信する。正常時は①のSCR-002へ移動し、ログインと現在のオリジナル手を維持する。

観戦画面・対戦結果画面の②・③は「ルームへ戻る」でこの画面へ戻ってから退出する。別タブも次の状態確認で①のSCR-002へ移動する。

## 10. ルーム設定

ホストの場合：

```text
対戦ルール

3勝先取
オリジナル手の連続使用：可能

[ ルールを変更 ] ← 開くと以下のフォーム

ルールの変更（ホストのみ・対戦中は変更不可）
先取勝数
[ 3 ]
1～99の整数

[ ] 同じオリジナル手の連続使用を不可にする

[ ルール変更 ]
```

補足：

```text
通常のグー・チョキ・パーは連続して選択できます。
```

対戦中は編集不可。

要約はホスト以外にも表示し、連続使用禁止ONを「不可」、OFFを「可能」とする。ルームと対戦画面の利用者向け表記を「オリジナル手の連続使用：可能／不可」に統一する。不可は同じオリジナル手の連続使用だけを制限し、通常手は制限しない。チェックボックスは「同じオリジナル手の連続使用を不可にする」とし、内部の禁止設定への対応は変えない。「ルールを変更」はホストかつ対戦中でない場合だけ表示し、通常は閉じる。開閉で入力値を消さない。先取勝数または連続使用禁止の入力エラーではフォームを開き、入力値と項目エラーを表示する。状態確認で要約は最新値へ更新するが、編集済み・エラー再表示のフォーム値は上書きしない。ホスト権限を失うか対戦が始まった場合は閉じて非表示・送信不可にする。

先取勝数の直下に入力前から「1～99の整数」を表示し、入力のaria-describedbyに`targetWins-hint`を設定する。エラー時は`targetWins-errors`も併せて参照する。定期更新でホストへ移譲されフォームを生成する場合も同じ補足と関連付けを用いる。入力範囲・サーバー検証・再表示入力と保存済みルールの分離は維持する。

768px以上のルール要約はflex配置で2項目を横並びにし、列間32px・折り返し行間8pxとする。各項目の文字と間隔が利用可能幅へ収まらなければ次行へ折り返し、長い文字列は項目内でも折り返す。768px未満は従来の縦並びを維持する。

### 11.2 ユーザー名重複


### 11.3 手名重複

```text
準備完了中のプレイヤーとオリジナル手の名前が重複しています。
```

複数エラーはまとめて表示する。

前回対戦からオリジナル手を更新していなくても警告を表示しない。

本人への案内は、②・未作成で `対戦前に、自分の手を1つ作りましょう。`、②・作成済みで `手を確認したら、準備完了を押しましょう。`、③で `あなたは準備完了です。設定を変えるときは「準備取消」を押してください。` とする。準備操作領域には「準備完了が2人以上で、対戦中でなければホストが開始できます。」を表示する。

準備操作の近くに、保存済みの本人手名と「保存済みの相性を確認」リンクを表示し、下部の既存設定領域へ案内する。未保存のフォーム値は使用しない。未作成時はこの要約を隠す。別タブの保存・削除は既存HTML取得から同期し、③では編集不可を維持する。同じ状態の定期更新では準備フォームを置き換えず、フォーカスを保つ。

②・③の待機案内は、対戦中なら「現在の対戦が終わるのを待っています。」、参加者が2人未満なら「参加者が2人必要です。ルーム名を共有して相手を招待してください。」、それ以外で準備完了者が2人未満なら③は「相手の準備完了を待っています。」、②は「準備完了が2人必要です。手を保存して準備完了を押してください。」、2人以上なら本人がホストの場合「対戦を開始できます。」、それ以外は「ホストの対戦開始を待っています。」とする。人数・本人状態・ホスト変更に応じて更新する。

## 12. 対戦開始

ルーム画面を表示しているホストには「対戦開始」ボタンを常に表示する。非ホストには表示しない。

| 表示対象 | 進行中対戦 | ③の人数 | ボタン |
|---|---|---|---|
| ホスト | なし | 2人以上 | 表示・有効 |
| ホスト | なし | 0人または1人 | 表示・無効 |
| ホスト | あり | 人数を問わない | 表示・無効 |
| 非ホスト | 有無を問わない | 人数を問わない | 非表示 |

ホスト自身が②でも、他に③が2人以上存在し、対戦中でなければ有効にする。ホスト自身の準備完了は必須条件にしない。

無効時も文言と配置を維持し、既存のBootstrapボタンのdisabled状態による淡い背景・枠・文字の見た目で、有効時と区別する。HTMLのbutton要素にdisabled属性を設定し、マウス・キーボードによるボタン操作と送信を禁止する。見た目だけの無効化やaria-disabled属性（支援技術へ無効状態を伝える属性）だけでは代用しない。サーバー側の開始条件検証は維持する。

初期表示と2秒間隔の正常な状態確認で同じ表を適用する。準備完了者が1人→2人なら有効化し、準備取消・退出等で2人→1人なら表示したまま無効化する。対戦開始後もルームに残るホストには無効表示を維持し、終了後は開始条件を再び満たした場合だけ有効化する。ホスト移譲では新ホストに現在の条件に応じた状態で表示し、非ホストには表示しない。④になった本人や退出した本人の画面遷移は既存仕様を優先する。

②・③は対戦開始だけで観戦画面へ強制移動しない。ルーム画面で参加者・ホスト・ルール・準備操作を更新し、本人の入力中フォームは状態が許可する限り保持する。

対戦中は、

```text
現在対戦中です

[ 対戦を見る ]
```

を非参加②・③へ表示する。

## 13. SCR-004｜対戦

### 13.1 共通表示

表示順はPC・スマートフォンとも、ラウンド番号と簡潔なスコア、手選択または待機、参加者の詳細・履歴・ルール、退出とする。

参加者の冒頭は「あなた ○勝 ・ ○勝先取」と1行にまとめる。観戦者は「○勝先取 ・ 観戦中」。対戦開始時の参加者と各勝数は、手選択後の「参加者の詳細」で開閉する。本人の勝数を重複して大きく表示しない。

「ラウンド履歴を表示」の開閉と、参加者向けの「対戦ルール」の開閉をその後に置く。ルールは対戦開始時に固定された値を表示する。観戦者へ選択用Modelや未公開の設定は追加しない。

### 13.2 対戦参加者

「ボタンを押すと確定します。確定後は変更できません。」と案内する。「通常手」「オリジナル手」の小見出しで区別し、オリジナル手には「対戦開始時に固定された全員の手から選べます。」と表示する。

通常手：

```text
[ グー ]
[ チョキ ]
[ パー ]
```

対戦開始時に固定されたオリジナル手：

```text
[ ドラゴン ]
[ 炎 ]
[ 水 ]
```

を表示する。

全員の手が確定するまでは他人の選択内容を公開しない。HTMLや状態JSONにも含めない。

ページと手確定フォームにmatchId・roundNumber・roomIdを制御用に保持する。手確定の送信はmatchId・roundNumberを含み、古い対戦・ラウンドの要求は拒否する。内部IDは利用者向けの表示や入力項目にしない。

本人の手が確定した後は、同一ラウンドの手選択ボタンを操作不可にする。連続クリックや再送による二重確定もサーバー側で拒否する。

同一ユーザーの別タブで手を確定した場合も、次の正常な状態確認で本人の選択手を反映し、通常手・オリジナル手の全選択ボタンを操作不可にする。他参加者の確定を待つ間に、本人の選択を再確定・変更できる表示を残さない。

状態確認のselfHandConfirmed・selfSelectedHandを、表示中のmatchId・roundNumberと一致する対象にだけ適用する。同じラウンドで確定済みとなったボタンは、遅れて届いた未確定の応答で再有効化しない。次ラウンドでは未確定表示へ更新するが、同一オリジナル手連続使用禁止に該当する手は引き続き選択不可とする。結果表示中・終了・退出時は既存の遷移条件に従う。

④の参加者には詳細・履歴・ルールの後、区切り線の下に次を表示する。

```text
[ ルームを退出 ]
```

手確定後に他参加者を待つ間も退出ボタンは操作可能。表示中のroomIdをroomActionFormでPOST /room/leaveへ送信し、正常時はログイン・現在のオリジナル手を維持して①のSCR-002へ移動する。対戦途中退出の処理は機能仕様22節に従う。

### 13.3 同一オリジナル手連続使用禁止

設定ONかつ直前ラウンドに本人が同じオリジナル手を選んでいた場合、その手だけ選択不可にする。

例：

```text
[ グー ]
[ チョキ ]
[ パー ]

[ ドラゴン ]  ← 選択不可
[ 炎 ]
[ 水 ]

前のラウンドと同じオリジナル手は選択できません。
```

通常手は直前ラウンドと同じでも選択可能。

### 13.4 観戦モード

②・③の観戦者には、

- 現在ラウンド
- 先取勝数
- 参加者
- 累積勝数
- ラウンド履歴
- `ルームへ戻る`

を表示する。

手選択UIは表示しない。

## 15. SCR-005｜ラウンド結果

冒頭で「結果を確認したら、そのままお待ちください。自動で次の画面に進みます。」とカウントを案内し、その後に結果表、既存履歴、退出を置く。

### 勝者あり・未決着


### 勝者なし

```text
このラウンドの勝者はいません

次のラウンドまで 5 秒
```

### 最終ラウンド

```text
対戦結果まで 10 秒
```

結果表の後に履歴の開閉領域を配置する。初期非表示で、「ラウンド履歴を表示」という固定文言の見出しを押して開閉する。観戦者の「ルームへ戻る」は履歴領域より前、参加者の退出操作は履歴領域の後に配置する。

未決着結果の表示中に残り2人以上となる退出があっても、このラウンドの表示・勝数・カウントの期限を変更しない。最終結果確定前に残り1人以下なら即時中止画面へ進む。

④の参加者には結果とカウントの下に次を表示する。

```text
[ ルームを退出 ]
```

未決着結果・最終ラウンド結果の双方で操作可能とし、表示中のroomIdをroomActionFormでPOST /room/leaveへ送信する。正常時はログイン・現在のオリジナル手を維持して①のSCR-002へ移動する。最終勝者確定後の退出では、確定済み正常結果と終了予定時刻を維持する。

ページのmatchIdを保ち、サーバーの対象状態に従って次ラウンドまたは同じ対戦の結果へ移る。結果表示が遅れて次対戦が進んでいても、対象対戦IDを取り違えない。

観戦者には、

```text
[ ルームへ戻る ]
```

を表示する。

### 15.1 カウントと実際の遷移

5秒・10秒はサーバー上の期限を表す。サーバーは期限前に自動遷移せず、期限到達後の次回500ms間隔のMatchTransitionScheduler実行で状態を更新する。ブラウザーは、その変更後の次回2秒間隔の状態確認で画面へ反映する。表示カウントが0になってもサーバー未遷移なら確認を継続し、画面だけで次ラウンドや終了を確定しない。

30秒の通信切断期限は、1秒間隔のDisconnectMonitorが期限到達後に最新状態を確認して処理する。切断による画面変更も次回状態確認で反映する。実時間での完全一致は要求しない。最終勝者確定後は実際の正常終了処理まで、残存参加者の④と正常結果を維持する。

### 16.2 対戦中止

```text
対戦終了

参加人数が不足したため対戦を終了しました

勝者はいません

最終結果
...

ラウンド履歴（常時表示）
...

[ オリジナル手の相性を表示 ]

```

### 16.3 閲覧対象と最終結果

対象対戦のルームに現在所属する②・③は、対戦に参加していなくても閲覧可能。

最終結果には対戦開始時の全参加者名と最終勝数を表示する。途中退出者と0勝の参加者も表示し、開始時点の名前を使用する。

最終結果の後、相性表示ボタンより前に「ラウンド履歴」を常時表示する。開閉ボタンは設けない。各ラウンドの表示は14節に従い、履歴がない場合は「確定済みのラウンドはありません」と表示する。通常終了・中止とも同じ配置とする。

### 16.4 終了後の状態と「ルームへ戻る」

正常終了時は最終ラウンドの10秒期限到達後の次回Scheduler実行による終了処理時、対戦中止時は中止確定時に、同じルームに残っている当該対戦参加者を④→②とする。画面はサーバー変更後の次回状態確認で反映する。

非参加の観戦者は②→②、③→③のままとする。

「ルームへ戻る」はそのタブを現在ルームへ移動するだけで、②・③と他タブの結果対象を変更しない。

この画面のURLは `/match-result?matchId=対象対戦ID` とし、再読み込み・フォームの保存／削除後も対象を維持する。内部IDは画面本文に表示しない。

### 16.5 次対戦開始時の画面制御

この画面を閲覧中の②は、次対戦が始まっても本人が「ルームへ戻る」を押すまで同じ結果画面を維持する。次対戦が終了しても結果を置き換えない。

③も、本人が次対戦に参加しない間は同じ結果を維持する。

ただし、別タブ等で準備完了した本人が次対戦開始で③→④になった場合は、新しい対戦画面へ自動遷移する。既にラウンド結果表示中ならラウンド結果画面へ遷移する。

結果はタブごとに対象を保持する。別タブでルームへ戻る、観戦する、別結果を開く等の操作では、このタブの対象を変更しない。

画面表示中も2秒間隔の状態確認を継続し、退出・切断・ログアウト・別ルーム所属時にはアクセス制御に従って画面を移動する。④への変化は全タブで新対戦を優先する。

## 18. 対戦結果からのオリジナル手編集

相性表を展開した際、現在ユーザーが②なら導線を表示する。

編集導線は、初回表示・再読み込み時に②である場合に生成する。表示中に別タブの操作で②→③になった場合、次の正常な状態確認で編集部分を非表示・無効化する。その後に準備取消で③→②へ戻っても、自動では復帰しない。初回表示が③だった場合も、②になってから同じmatchIdのURLを再読み込みすると編集導線を表示する。現在の画面には再読み込み専用ボタンを設けず、ブラウザーの再読み込み（Windowsでは`Ctrl + R`）を使用する。

再読み込み時に未保存の入力値は引き継がず、保存済みの現在の設定を取得する。表示対象の終了済み対戦IDと過去の相性表は維持し、最新結果へ置き換えない。④や退出・切断・ログアウトに変化した場合は、既存のアクセス制御・画面遷移を優先する。

### 作成済み

```text
[ 自分のオリジナル手を編集 ]
```

### 未作成

```text
[ オリジナル手を作る ]
```

押下すると同じ結果画面内へフォームを展開する。

③の場合は導線を表示しない。

作成・更新・削除後も同じ結果画面へ戻り、画面上部の終了済み対戦相性表は更新しない。入力不正ならフォームを展開したまま入力値と項目エラーを表示する。

更新せずルームへ戻り、後で準備完了しても警告しない。

共通編集部品内の本人の保存済み要約は6節に従う。終了済み対戦の相性表とは分離し、本人の現在値を過去相性へ混ぜない。結果画面ではルーム画面のような保存済み設定の自動取得は行わず、再読み込みで現在値を取得する。

## 19. レスポンシブ

共通：

- フォーム・参加者名・履歴は画面幅に収め、長い文字列を折り返す。
- 手ボタンは通常3列とし、各ボタンを個別のPOSTフォームとして配置する。
- 相性表は最小幅580pxを確保し、表示領域を超えた場合は横スクロールする。
- 勝利表示の文字ラベルを必ず残す。
- 参加者一覧は通常2列とする。相性4項目はフォームの実際の幅に応じ、1列の最小幅を21rem（領域が狭い場合は100%）として自動的に列数を決める。画面幅だけで常に2列としない。項目間は1rem空ける。
- 相性の説明用例表は幅100%・固定の列配置とし、セル内で折り返す。終了済み対戦の相性表の最小幅580pxとは区別する。
- 背景画像の切替は768pxを境界とし、以下の配置切替とは区別する。
- SCR-003の密度調整は768px以上に限定する。主要領域32px、手設定20pxの内側余白と、7節の上下余白を適用する。ルール要約は利用可能幅による折り返しを許可する（10節）。768px未満は既存の`clamp(1.25rem, 4vw, 2.5rem)`の主要領域内側余白を維持し、575.98px以下の手設定内側16px・操作領域・左右余白を縮めない。

575.98px以下：

- 共通ヘッダーのロゴとユーザー操作欄を2段に配置する。
- 手ボタンは2列へ切り替える。間隔は約12px、高さ44px以上（現行は80px以上）を保ち、候補が多い場合は縦スクロールする。文字やボタンを小さくして詰め込まない。すべてを1列へ並べる仕様にはしない。
- 主要コンテンツの幅は画面幅から左右合計1.5remを引いた幅とし、余白と編集部品の内側余白を縮める。
- 参加者一覧は1列、準備領域の操作と入室ボタンは幅いっぱいに配置する。相性の各選択グループ内は勝ち・負け・引き分けを縦並びにし、ラベル全体を操作領域とする。
