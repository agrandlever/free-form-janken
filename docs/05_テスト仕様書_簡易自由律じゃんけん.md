# テスト仕様書：簡易自由律じゃんけん

## 1. テスト目的

要件定義書、機能仕様書、API設計書、画面設計書に定義した仕様どおりに動作することを確認する。

主な対象：

- 簡易ログイン
- ログアウト
- ルーム作成・参加
- ルーム名コピー
- オリジナル手
- 対戦準備
- ルーム設定
- 対戦開始
- 勝敗判定
- ラウンド自動遷移
- ラウンド履歴
- 観戦
- 通信切断
- 対戦終了
- オリジナル手相性公開
- 対戦後のオリジナル手編集
- 状態・権限制御

## 2. テスト前提

- Java / Spring Bootでアプリケーションを起動できる。
- 複数ブラウザセッションを用意できる。
- DBは使用しない。
- 状態確認は2秒間隔。
- 通信切断判定は30秒。
- 1ルーム最大8人。
- 先取勝数は1～99。

## 4. 主要テストケース

### TC-004｜存在しないルーム名で新規作成

前提：

- ユーザーは①。
- `自由律部屋` は存在しない。

操作：

1. ルーム名に `自由律部屋` を入力。
2. `ルームへ入る` を押す。

期待結果：

- 新規ルームが作成される。
- 操作者がホストになる。
- 操作者が②になる。
- 先取勝数3。
- 同一オリジナル手連続使用禁止OFF。

### TC-005｜存在するルーム名で参加

前提：

- `自由律部屋` が存在する。
- 参加者7人以下。

操作：

別ユーザーが `自由律部屋` を入力し `ルームへ入る`。

期待結果：

- 新規ルームを作成しない。
- 既存ルームへ参加する。
- ②になる。

### TC-009｜同名ルーム二重作成防止

- 片方は作成者。
- もう片方はそのルームへ参加する。

- ③は準備対象から外れる。ホスト退出時の移譲、最後の1人退出時のルーム削除はTC-011・012・106に従う。
- ④の途中退出による継続・中止・確定済み結果保持はTC-061・063・096～098に従う。最終勝者確定後は、退出した勝者と正常結果を維持する。
- 対戦終了時に退出した本人を②へ戻さず、保存済み結果・固定済みオリジナル手は変更しない。
- 同一セッションの別タブは次の状態確認で①を検知してSCR-002へ移動する。GET /api/statusはログイン済み①の正常応答を返す。
- 退出後、同じセッションで別ルームへ入室でき、保持したオリジナル手を利用できる。
- 退出直後に①のまま同じ退出フォームを再送した場合は409で拒否する。別ルーム入室後の旧フォームはTC-116に従い拒否し、現在所属を変更しない。

## 10. 別タブの本人手確定状態の反映

### TC-130｜別タブで確定した本人の手を状態確認で反映

前提：

- A・B・Cが同じ対戦のactive参加者④で、手選択中。
- Aは同一セッションの2タブで同じmatchId・roundNumberのSCR-004を表示し、両方で未確定。
- B・Cは未確定に保ち、Aだけが確定してもラウンドが終了しない条件にする。
- 次ラウンドの確認では対戦が未決着となるようにし、通常手とオリジナル手を選ぶ場合を別々に用意する。
- 同じルームの②・③観戦者と、時刻・応答順を制御できる条件も用意する。

操作：

1. Aの両タブで、現在のmatchId付きGET /api/statusを確認する。
2. 一方のタブから有効な手を確定し、他方のタブではページを手動で再読み込みせず次の正常な状態確認を行う。
3. 他方のタブから同じラウンドへの手確定要求を直接再送する。
4. 未確定時点で取得した古い応答を、確定済みの反映後に遅延到着させる。
5. B・Cを確定させ、ラウンド結果の表示後に未決着の次ラウンドへ進める。連続使用禁止ONでAがオリジナル手を選んだ条件も確認する。
6. 観戦者、matchId無指定・UUID形式は正しいが不存在・他ルーム指定、ROUND_RESULT、終了済み結果の各応答も確認する。UUID形式不正は別に確認する。

期待結果：

- Aが未確定ならselfHandConfirmed=false、selfSelectedHand=null。
- Aが確定し、対象がまだSELECTING_HANDなら、両タブへselfHandConfirmed=trueと本人の同じ確定済み手を返す。type・normalHand・originalHandId・handNameはAPI26節の構造と固定済み手名に従う。
- 他方のタブも次の正常な状態確認で、通常手・オリジナル手の全選択ボタンを無効化し、本人の選択手と他参加者を待つ状態を反映する。
- AへのHTML・状態JSONにB・Cの確定前の選択手や公開前の相性を含めない。本人の選択を取得するために、送信ユーザーIDを信用しない。
- 直接再送は409 / INVALID_STATEで、本人の確定済み手・勝数・履歴・対戦状態を変更しない。
- 同じmatchId・roundNumberで遅れて届いたfalseの応答は、確定済み表示とボタンの無効状態を戻さない。別の対戦・ラウンドの確定情報も現在画面へ適用しない。
- ROUND_RESULTでは既存のラウンド結果画面へ進み、次ラウンドでは新しい番号と未確定状態へ更新する。連続禁止ONなら直前と同一のオリジナル手だけは引き続き選択不可で、通常手とほかの使用可能手は選択できる。
- ②・③の観戦者、matchId無指定・UUID形式は正しいが不存在・他ルーム指定、ROUND_RESULT、終了済み結果の正常応答ではselfHandConfirmed・selfSelectedHandともnull。観戦者へ手選択UIを提供しない。
- matchIdのUUID形式不正は400のJSONエラーとし、正常応答の本人手確定情報を返さない。未ログインは401のJSONとする。
- ①・ログアウト・別ルーム所属になった場合は既存のアクセス制御を優先し、本人の確定情報によって旧画面を維持しない。
